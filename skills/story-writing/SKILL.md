# Story writing

创作、改写或审核故事前，完整阅读 `references/story-rules.md`。该引用文件是故事结构、逐词关联、谐音因果和正反例的唯一详细规范。

## Workflow

1. 先确定候选表达；它可以是日常用语、流行语、祝福、情话、晚安、道歉或其他自然短句，不限定题材。
2. 为候选表达设计字面谐音句。逐个拆出其中的主角、动作、对象、状态和结果；每个实词都必须能在故事前文找到直接证据，并共同组成同一条因果链。
   先建立“目标表达 → 字面事物/动作”的逐音节映射表；不能只替换最后一个字，也不能让前文出现与谐音无关的同名角色。
3. 先验证字面故事，再验证谐音。遮住谐音原句后，字面句仍须是对故事自然、完整且必要的概括；不能为了读音临时加入无关角色、物品或动作。
4. 默认用 8 页组织：主角或事物登场 → 原始环境或状态 → 问题或负面反应 → 条件改变 → 明显结果 → 提问 → 字面谐音句 → 真正表达。根据因果链在 7–9 页内自然调整，不为凑页数添加无关内容；用户另有页数或文案要求时以用户要求为准。
5. 每页只写一个可直接画出的完整情节，不依赖插画内部文字。分页旁白要简洁但必须讲清“谁做了什么、发生了什么结果”；可使用一至两句短句，不能压缩成只有“发现大梨”“一起玩”这样的情节标签。复杂的动作、表情、道具和构图可另列为画面细节，但旁白本身读完也应能看懂故事。除非用户明确要求改写，否则保留用户故事的页序和文案。

## Strict output rules

- 用户要求“生成故事”“看看故事”或类似创作时，默认直接按项目分页格式输出：故事名、`谐音：`、`图1` 至 `图N`；不要自行改成其他模板。
- 默认 8 页。倒数第二页只能写字面谐音句，最后一页只能写对应的真实表达；不得添加“原来是：”“真正表达是：”“对应的是：”等揭示前缀，也不得在最后一页补解释。
- 如果用户要求查看示例，必须优先读取并引用 `story/故事.md` 中已有故事；不能把临时生成的故事称为项目示例。
- 分页模板优先参考 `story/stories/鱼见泥/story.txt`：这是项目现成的 9 页模板，结构为“铺垫 → 情绪反差 → 提问 → 字面谐音句 → 真正表达”。其中图7提问，图8直接回答字面谐音句，图9直接放真实表达。
- 没有通过下方验收清单的候选，不得作为合格故事直接交付；应淘汰候选并重新设计，或明确标为未通过的草案。
- 未经用户要求，不把创作结果写入 `story/故事.md` 或 `story/stories/<故事名>/story.txt`；确认文案后才进入后续生图流程。

## Acceptance checklist

- 逐词关联：谐音句中的每个实词都有前文证据，不存在只为凑音加入的词；`很久`、`一直`、`特别` 等时间或程度修饰也必须有明确铺垫。
- 谐音贯穿：目标表达中的每个关键音节，都必须在前文由对应的角色、物品、动作或结果承担；最后一页只能汇总和揭示，不能首次引入谐音所需的关键事物。
- 音义双重关联：字面事物不仅要读音接近目标词，还要在故事中执行与目标词意义相符的动作。例如“耗象马上箭到泥”中，耗子对应“好”、大象对应“想”、马对应“马上”、射箭对应“见/箭”、箭落到泥里对应“到泥”，所有元素共同指向“好想马上见到你”。
- 全句回收：遮住最后两页后，读者仍能从前文复述出目标表达里的主要音节和情节；若只在末页把一个角色名替换成谐音，判定为不合格。
- 同链关联：主角、动作、对象、状态和结果彼此直接发生关系，不是分别出现过就算成立。
- 字面成立：不知道谐音原句时，落梗句仍是符合正常中文语序和搭配的完整表达，并能自然解释故事结果；不能把“名词出现了”和“状态出现了”直接压缩成生造短语。
- 谐音完整：真正表达的每个关键音节都须在字面句中有清楚对应；不能省略音节，也不能用读音不同的语气词补成目标表达。
- 因果闭环：条件变化确实导致结果；倒数第二页用字面谐音句回答提问，最后一页只揭示对应的真正表达。
- 第一页一眼产生好奇；每页只表达一个画面。
- 优先使用新鲜且清楚的谐音，避免反复使用 `泥=你`、`梨=你` 等高频替换。
- 若逐词解释需要额外编造设定，或落梗只能作为口号而不能解释情节，淘汰候选并重新选梗。

## Pre-delivery self-check

交付前逐条检查，并在内部确认通过：

1. 是否完整读取了 `references/story-rules.md`，并按其中规则设计故事？
2. 目标表达的每个关键音节，是否都有前文的角色、物品、动作、状态或结果承担？
3. 遮住最后两页后，是否仍能复述出完整因果链？
4. 第 N-1 页是否只有自然的字面谐音句，第 N 页是否只有真实表达？是否完全没有“原来是”等自加揭示语？
5. 每页是否只有一个可直接绘制的完整情节，且没有首次出现在结尾的关键元素？
6. 是否严格采用项目的 `图1`、`图2`……分页格式，并避免把画面提示词混进旁白？

## Canonical example

项目模板《鱼见泥》如下；需要生成同类故事时，优先沿用它的节奏和收尾方式：

```text
图1
从前有一条鱼
图2
在清澈的溪水里游来游去
图3
可它总是不开心
图4
朋友把它捞到泥滩上
图5
小鱼突然蹦蹦跳跳
图6
笑得眼睛都弯了
图7 你知道为什么吗？
图8 因为鱼见泥就很开心呀
图9 遇见你很开心
```

不要把模板改写成“原来是：真正表达”或其他自创揭示格式。

## Output locations

- 候选故事、分类目录和故事文案：`story/故事.md`
- 故事确认后，将对应分页文案复制到：`story/stories/<故事名>/story.txt`
- `story.txt` 是 `story-image-generation` 和 `story-publishing` 的后续输入，不要在未确认文案前开始生图。
